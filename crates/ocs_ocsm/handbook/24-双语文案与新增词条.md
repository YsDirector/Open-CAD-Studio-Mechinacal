# 24 双语文案（中/英）与新增词条

> 用户 2026-09-27 定案：**给 OCSM 做全量英文翻译，使其同时支持中英双语**。
> 本文件是开发侧说明（怎么加词条、怎么切语言、怎么测）；全量字符串规模与分批计划见
> `~/桌面/OCSM/review/i18n_盘点.md`（阶段 1 盘点，2026-09-27）。

## 一、三条不变的口径（用户定的）

1. **卡面文字也要英译**（不只界面）。实现路线：**卡定义只有一份，卡面标签随语言渲染**
   —— **禁止**给每张卡再复制一份英文卡。
2. **标准符号不译**：`D_ei` / `Az` / `Wn` / `Kn` / `d_B` / `m` / `z` / `αD` / `MM` / `IT` … 保持原样。
3. **语言机制**：跟随宿主语言 + 可手动覆盖；所有面向用户的中文文案必须进**单一 catalog**，
   不得散落硬编码字符串（命令关键字/查表键/图层名等**协议记号**除外，见 §六）。

## 二、代码位置与取词 API

* 单一 catalog：`crates/ocs_ocsm/src/i18n.rs`（`CATALOG`，表驱动，**一行一 key：`zh` / `en`**）。
* 取词：
  * `i18n::t("cmd.tf.usage")` —— 按当前语言取词，返回 `String`（按需要可加 `_lang` 变体）；
  * `i18n::t_fmt("cmd.tf.err.unknown_param", &[("arg", tok), ("usage", &usage)])`
    —— `{name}` 占位符插值；**两语的占位符集合必须一致**（`catalog_problems()` 会查）；
  * `i18n::t_lang(i18n::Lang::En, key)` / `t_fmt_lang(...)` —— 显式语言（测试/GUI 预渲染）。
* 语言：
  * `i18n::lang()` / `i18n::set_lang(i18n::Lang::En)` / `i18n::set_lang_auto()`；
  * `i18n::env_lang_source()` 返回当前生效的环境变量与值（排查用）。

### 语言来源（优先级从高到低）

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | `i18n::set_lang()` | 程序内覆盖：GUI 语言切换 `/api/i18n?lang=`、命令开关、单测 |
| 2 | 环境变量 `OCSMLANG` | 手动覆盖，如 `OCSMLANG=en`（部署/调试最常用） |
| 3 | 环境变量 `OCSM_LANG` | 兼容别名 |
| 4 | `LC_ALL` → `LC_MESSAGES` → `LANG` | 宿主/system locale 的代理（值认 `zh*` / `en*`，大小写与 `.UTF-8` 后缀不敏感） |
| 5 | 默认 `zh` | 保守默认：既有输出全中文，缺省不改变现行为 |

> 宿主 API（`ocs_plugin_api::host::HostApi`）目前**没有**语言/locale 字段（已逐方法核对），
> 所以阶段 1 用环境变量兜底；**没有改** `ocs_plugin_api/**`。将来宿主暴露语言设置时，
> 只需要改 `resolve_env_lang()` 一处，其余调用点不动。

### 缺 key 的保守默认（绝不返回静默空串）

* key 在 catalog、目标语言串为空 → **回落 `zh`**，并记入 `i18n::missing_keys()`；
* key 完全不在 catalog → 返回 **key 本身**（可见占位，一眼定位），并记入 `missing_keys()`；
* 运行期不 panic；缺失由 `catalog_problems()`（静态）与 `missing_keys()`（运行期）兜住。

## 二·补、GUI 页面文案怎么进 catalog（阶段 2 ① 批）

页面（`*_gui.html`）与公共 JS（`ocsm_gui_common.js`）都是 `include_str!` 编进 `.so` 的**模板**：
模板里**不写中文兜底**，只写占位符；插件 HTTP 服务在**每次请求时**按当前语言渲染后再发出去。

| 占位符 | 用在哪 | 转义 | 写法 |
| --- | --- | --- | --- |
| `{{i18n:gui.xxx}}` | HTML 文本节点 / 属性 | HTML 转义 | `<h1>{{i18n:gui.parts.h1}}</h1>` |
| `{{i18njs:gui.xxx}}` | `<script>` 里的 JS 字符串字面量 | JS 字符串转义 | `el("s").textContent = "{{i18njs:gui.parts.export}}";` |

* **插值**：catalog 里写 `{name}`，页面 JS 用 `.replace("{name}", v)`，例如
  `"{{i18njs:gui.parts.err.not_number}}".replace("{label}", it.label)`；
  `catalog_problems()` 会查两语占位符集合一致。
* 禁在 HTML/JS 里另写中文常量（“catalog 是唯一来源”）；命令关键字/图层名/标准符号仍不译（见 §六）。
* 实际入口（`guide_server.rs`）：`render_i18n_text[_lang]()`（占位符替换）＋
  `render_page_i18n()`（页面再注入语言控件）；`page_response()` 每个页面都走它；
  公共 JS 路由 `/ocsm_gui_common.js` 也走同一替换。
* **语言切换入口**：服务端在 `</body>` 前注入悬浮控件 `#ocsmlang`（标签也来自 catalog，
  `data-lang` 标当前语言）；点另一个语言 → `GET /api/i18n?lang=en|zh` → 刷新页面。
  切语言是**进程级**的（`set_lang`）：一张图切了，所有 OCSM 窗口/命令行都跟着变；
  宿主环境变量（`OCSMLANG`/locale）仍是初始默认。
* `GET /api/i18n[?lang=…]` 返回 `{ok, lang, languages, source, catalog}`（当前语言全表，联调/诊断用）。
* 新页面接线清单：① 在 `i18n.rs` 的 GUI 分节加词条并过 `catalog_problems()`；
  ② HTML/JS 换成 `{{i18n*:…}}` 占位符；③ 如果 JS 里要取值，用 `.replace("{…}", v)`；
  ④ 直接跑七条 smoke（`tests/i18n_zh_fixture.mjs` 会按 zh 渲染占位符，测试专用，不是产品兜底）。

## 三、新增一条词条（清单）

1. 在 `i18n.rs` 的 `CATALOG` **对应分节**加一行：`Msg::new("域.对象.用途", "中文", "English")`。
   分节：命令输出 / 报错 / GUI / 卡面标签 / 计算书 / 手册（键名前缀 `cmd.` / `gui.` / `card.` / `report.` / `doc.`）。
2. 把产品路径上的硬编码替换成 `i18n::t(...)` / `i18n::t_fmt(...)`
   —— **只限「推给用户 / 写进图纸 / 进 GUI」的字符串**；命令关键字、查表键、图层名不进 catalog（§六）。
3. 需要插值就写 `{name}` 占位符；**中英两语占位符必须同名齐全**。
4. 卡面/图纸标签：卡定义只一份，标签在渲染时取词；同一句话在 GUI 与 ATTDEF 两处出现时
   **必须共用同一 key**，否则同词两处不一致。
5. 测试：
   * `cargo test` 下语言覆盖是**测试线程内**的（`i18n::set_lang` 走 `TEST_OVERRIDE` 线程局部，
     见 §八）；产品构建仍是进程级（GUI `/api/i18n`）。
   * `set_lang(Zh)` → 断言中文；`set_lang(En)` → 断言英文；结束 `set_lang_auto()`；
   * 断言中文文案的既有用例与「切语言」用例仍建议拿 `global_state_test_lock()`
     （串行化环境变量等其它全局状态，仓库既有惯例）；
   * 竖切样例见 `lib.rs::tests::tf_usage_and_unknown_param_switch_language_via_catalog`
     与 `i18n::tests::*`（完整性 / 回落 / 切换 / 插值 / 环境解析）；
     ② 批样例见 `hole::tests::hole_messages_switch_language_with_data_intact`（10 类报错 + 关键数据）、
     `hole::tests::hole_paths_leave_no_missing_catalog_keys`（`missing_keys()` 为空）、
     `centerline::tests::centerline_messages_switch_language_keeping_data`、
     `guide_server::tests::command_catalog_summaries_are_bilingual_and_render_per_language`。
6. 门禁（照仓规）：`cargo test -p ocs_ocsm --lib`（10 连跑）、`cargo build --release -p ocs_ocsm`
   （只编译，别部署到用户主插件目录）、七条 smoke（各自正确 HTML 路径）。

## 四、语言怎么用（用户侧）

* 默认跟随系统 locale；想强制英文（或中文）：

  ```sh
  OCSMLANG=en   # 开 OCS/插件；或写进启动环境
  OCSMLANG=zh   # 强制中文
  ```

* **GUI 里切换**（阶段 2 ① 批已可用）：每个 OCSM 页面右下角有悬浮的语言控件
  （`#ocsmlang`，显示「语言 / 中文 / English」）；点一下 → 插件进程级切换 → 页面刷新，
  所有 OCSM 窗口/命令行随后都按新语言出文案（**老图上已有的卡面/标注文字不会重写**，
  只影响新出表/新窗口）。

## 六、明确不翻译 / 不改造

| 对象 | 处理 |
| --- | --- |
| `assets/*.csv` 等标准数据 | **不翻**（标准原值/表号；`*_notes.md` 口径说明如需英文化另开单） |
| 命令关键字（`内`/`外`/`公称`/`平`/`圆`…）、查表键 | 不进 catalog；CLI 行为**不随语言变** |
| CAD 图层名/线型名/文字样式名（`1轮廓实线层`、`OCSM_GB`…） | 协议记号，图纸互通性优先，不译 |
| 标准符号、单位、纯数字格式模板（`{} mm`） | 不译/保持原样 |
| 注释、单测断言、`tests/*.mjs` 冒烟文案 | 不计入 catalog；改词条时同步测试 |

## 八、已知坑（踩过的）

* **`spline_gui.html` / `ocsm_gui_common.js` 是 `include_str!` 进 `.so` 的**：
  改页面必须 `cargo build --release` 并只在临时插件目录部署（别碰 `~/.config/OpenCADStudio/plugins/`）。
* **老图不翻译**：卡面标签进了 ATTDEF 就是图纸内容；语言切换只影响**新出表**。
* **页面 JS 里插值**不能直接拼中文字面量：写 `"{{i18njs:key}}".replace("{name}", v)`；
  HTML 上下文用 `{{i18n:key}}`（两种转义不同，别混用）。（阶段 2 ① 批）
* **语言是进程级全局**：产品构建 `set_lang` 写全局（GUI `/api/i18n` 选一次全插件生效）；
  **但 `cargo test` 里是测试线程内的**（`i18n.rs` 的 `#[cfg(test)] TEST_OVERRIDE`）。
  这是 ② 批踩的坑：若测试里 `set_lang` 也写全局，一个切 En 的用例会在并行跑时
  把断言中文文案的用例带崩（曾实测 20 次连跑 6 次假红）；线程局部覆盖后消失。
  断言中文文案的用例仍建议持 `global_state_test_lock()`（串行化环境变量等全局状态）。
* **老图上已有的卡面/标注文字不会被重写**；卡面标签/字段表标签仍归后续批次。
* `catalog_problems()` 只查静态问题；「这个 key 到底有没有人用」要靠运行期 `missing_keys()` + 人查。
